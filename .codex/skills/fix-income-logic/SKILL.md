# 收入逻辑修正

## 工作流程

1. 检查现状：records 表结构、录入界面（AddView）、明细与统计查询。
2. 数据层：确保 records 有 type（expense/income）；收入使用独立来源分类（工资、奖金、兼职、投资收益、红包、其他）。
3. 界面层：录入时选择“收入”显示收入来源单选；“支出”保持一级+二级分类。
4. 统计层：支出与收入分别汇总；明细中收入条目不显示支出二级分类。
5. 迁移：历史收入记录（如指向支出分类）自动改指“收入/其他”，保证幂等。
6. 验证：冒烟测试确认迁移与统计正确，构建并运行。

## 注意事项

- 所有数据库变更必须向下兼容，不丢失用户已有数据。
- 迁移逻辑需幂等（重复执行结果一致）。
