# 代码审查

## 工作流程

1. 扫描项目目录，列出核心源码文件（.js/.mjs/.vue/.html/.css/.json），排除 node_modules/dist/release。
2. 逐一阅读核心模块（数据层、主进程、渲染层、游戏逻辑、AI 算法），理解功能。
3. 按四类检查：
   - 逻辑正确性：金额/统计/合并/胜负判定等业务逻辑
   - 安全与健壮性：输入校验、异常捕获、定时器/事件监听是否清理
   - 规范与可维护性：模块拆分、命名、中文注释
   - 性能：渲染流畅度、查询索引、打包体积
4. 输出 Markdown 报告，结构：
   - 项目概览（名称、版本、审查文件清单、整体评分 A/B/C/D）
   - 🔴 严重问题（必须修复）：问题描述、文件位置（文件名+行号）、可能影响、修复建议（含示例代码）
   - 🟡 建议优化：同上但影响较小
   - 🟢 优点与亮点：值得保持的优秀实践
   - 综合评价与后续建议（技术债优先级排序）
5. 报告中技术术语附加通俗解释，确保非技术用户能理解。

## 注意事项

- 默认只输出报告，不直接修改代码；用户明确要求修复时才改。
- 问题必须可操作：每个问题都要有文件位置和具体修复建议。
- 报告需覆盖所有核心功能模块，至少给出 3 个风险点或优化建议（代码质量极高时说明“未发现明显风险”）。
